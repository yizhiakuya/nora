# 上下文整理可见性与 MCP 管理边界

## 需求与现状

- MCP 查询、接入、修改和验收统一使用现有 `manage_mcp`；凭据使用 `manage_env_vars`，缺少信息走 `ask_user`。手机通道的 Relay 路由不等于 MCP 注册，历史记忆不能覆盖当前工具定义。
- 自动整理在下一次模型请求前同步执行：输入达到窗口的 83% 时先缩短旧工具结果，再归档完整的早期助手/工具往返，目标为 65%；仍超阈值时尝试模型生成历史摘要。上游拒绝长度时整理至 60% 后重试。旧图片回收另按批次进行。未配置模型窗口时 128K 是整理预算。
- 当前整理步骤只保存统计，前端还将计费输出（含思考）直接累加到输入占用，导致展示混淆。

## 最小方案

1. 保留现有 MCP 工具和权限边界，在工具定义与系统规则中明确它是工作台 MCP 管理入口；补充 LOW 风险的 `get`，复用已有服务器查询，显示连接地址、状态和脱敏鉴权配置。URL 查询和用户信息隐藏，STDIO 参数不回读明文。修正误导的持久记忆与重复注册错误指引。安装启动依赖仍可使用终端，注册、改配置、连接测试不扫描源码或猜接口。
2. `ChatStepDto.ContextInfo` 增加可选 `content`。装配器记录本次变更消息，整理结束后仅展示仍在请求中的替换正文；后续被归档的中间摘录不混入。语义压缩展示检查点的工作摘要。沿用 step 的 SSE、重连、持久化，不增加 API、数据库列或额外摘要请求。
3. 自动整理使用 `context` 步骤，展开直接显示正文与统计；模型历史摘要单独标明。手动 `/compact` 使用同一正文契约。旧记录没有正文时保留已有统计，不能编造摘要。
4. 前端输入计量为最近请求的输入基线，加此后收到的正文、工具参数与结果、补充要求。展示用思考和整理视图不重复累加，`output_tokens` 仅用于计费。协议要求回传的思考保持 SDK 语义，由下一次请求的完整 input usage 计量；不删除签名/工具往返所需数据。

## 影响与验收

涉及上下文装配、步骤 DTO/生产者、前端 SSE 合并/计量/整理展示、MCP 工具定义、权威工具文档及对应冒烟与真实 E2E。无数据库迁移；历史、工作区原始归档、服务商与凭据保留。

检查真实请求与 SSE/历史中整理正文一致，思考增量不改变输入计量、工具输出仍每秒刷新，手动与自动语义摘要可直接查看；MCP 缺凭据应询问、已有服务复用管理入口。部署前确认运行空闲并备份。
