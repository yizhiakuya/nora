# 空回答无声结束修复

用户报告会话 `sess-1791188504375` 执行「打开你的内置浏览器」后直接结束。真实历史显示这轮持续 51.222 秒，先因缺少 URL 报错，再查询到空白浏览器；最终模型轮只有思考内容，没有回答或工具调用。日志记录该轮输出 8192 tokens，正文 0 字符，思考 32494 字符。旧解析器将思考内容计入成功条件，编排层随后接受空回答。原会话有六条消息，本次没有修改其历史。

原日志未记录 finish_reason，不能据此确定旧轮的上游停止原因。新增日志后，在同渠道、同模型、max 等级的真实重试中复现了 `finishReason=length`、输出 8192 tokens、正文 0 字符，确认这种上游输出限制可以触发同类故障。

## 修复

- 统一模型轮结果拒绝无正文、无工具调用的成功状态，覆盖 Chat Completions 与 Responses 两条协议路径。
- 只返回思考时立即报告 `LLM_NO_ANSWER`，保留失败步骤并提供重试提示；避免在同等级下盲目重复消耗模型输出，避免用原始工具 JSON 掩盖失败。用户取消仍优先处理。
- 无网址的浏览器 open 创建空白页或保留已有网页，传网址时继续校验 HTTP/HTTPS；工具说明区分打开浏览器与资料采集。
- 历史加载从服务端终止错误步骤恢复空回答的失败原因和重试入口，刷新后仍可见。
- 日志记录 Chat Completions 的 finish_reason/DONE 和 Responses 的完成或未完成原因。

没有调整用户的思考等级或上游输出上限。模型仍可能因上游额度耗尽而失败；本次保证不再将仅思考的输出当作正常交付。
