# Agent 环境变量工具

会话 `sess-1791438380456` 为保存 Tavily 密钥反复扫描运行环境和应用包。设置页已经提供变量存储，但 Agent 缺少对应工具。

## 最小方案

- `manage_env_vars` 只提供 `list / set / delete`。设置和删除只改指定变量，省略 `secret` 时按密钥处理。
- `EnvVarsService` 统一变量校验、遮蔽、单项修改和执行时读取；控制器、工具、命令和 MCP 都使用它。移除服务对控制器静态方法的依赖。
- 复用 `app_setting(env-vars)` 的数据格式。`AppSettingStore.update` 在数据库事务内锁住设置行，读改写原子完成；读取或校验失败时不覆盖已有配置。
- 设置页添加、删除也使用单项 API，避免旧页面快照覆盖 Agent 新存的其他变量。既有全量 PUT 保留其明确的全量替换语义，底层仍共用同一服务。
- 命令启动时注入变量，MCP 建立连接时解析 `${KEY}`。JSON 配置中的替换保留字符串转义；修改已连接的 MCP 所用变量后按需 refresh。
- `list` 为 LOW，`set/delete` 为 HIGH，遵循已有权限档位。工具参数、日志、审批和历史隐藏 value，标题仅显示动作和变量名；密钥查询与返回只给遮蔽值。原始值仅存储并交给执行层，用户原消息不由本工具改写。
- 上游请求日志只记录协议、模型和地址，避免请求正文再次记录凭据。MCP SDK 的参数根 Schema 包含标题时，剔除 SDK 不接受的 `title/$schema` 元数据，保留参数约束并继续使用 LangChain4j 解析。

## 验收

执行后端冒烟与前端现有质量门。真实服务 E2E 验证：模型原生调用、设置页/API 一致、更新保留其他变量、并发设置不丢数据、默认脱敏、非法输入回滚、权限审批、命令环境注入及 MCP 引用。只使用测试变量并清理，部署前检查活动轮次，保留服务器会话和配置。
