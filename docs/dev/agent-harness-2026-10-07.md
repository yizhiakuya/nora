# Agent 执行循环优化（2026-10-07）

依据 `docs/research/nora-harness-comparison-2026-10-07.md`，本轮改进现有执行循环，不增加规划器或恢复框架。

- 每次模型请求最多尝试 3 次，连接中断、HTTP 408/429/5xx 使用指数退避和随机抖动；取消立即停止等待。仅重试尚未流出文本、思考或工具调用的请求。当前 LangChain4j HTTP 异常不携带响应头，因此使用本地退避，不推断 Retry-After。
- 工具执行后的模型请求同样可以重试，继续使用已回填的工具结果，不重新执行工具。配置兼容与上下文超限恢复继续沿用已有路径。
- 未配置模型返回 LLM_NOT_CONFIGURED；编排异常及工具轮次耗尽按实际原因结束，删除强制 `tool_choice=none` 的兜底回答。上游错误原文保留。
- `POST /api/chat/sessions/{id}/steer` 接收 `{turnId,messageId(UUID),content}`。同会话保持一个执行循环；指令先落库，再在工具批次后的安全边界进入下一次模型请求。完成边界与受理共用锁，过期轮次拒绝新输入。重复提交同一 ID 幂等；未处理指令仍在历史中保留并标记。等待审批/提问时，补充要求在等待结束后处理。
- SSE 必须收到有效的 done 事件才算正常完成；error 原文保留，并继续接收后续 done 的计量。
- 提示词限制自行修改行为文件，明确实际产物验收与当前权限模式；不要求额外的固定规划/审查轮次。
- 运行完成与工具历史错误分开记录。任务业务成果是否通过验证仍由现有浏览器/导出等领域验收判断。

验收使用真实模型、真实工具和 SSE；故障测试只在真实上游前注入一次可重试 HTTP 错误，不模拟模型回答。

验收结果：后端相关冒烟 40 项、前端冒烟 123 项，类型检查、Lint、生产构建通过。真实模型透传故障验收（OpenAI / Anthropic / Responses）及补充指令、幂等、完成边界、取消共 23 项检查通过（另有 2 项未配置模型的失败验收通过）；工具并发、已处理错误的运行终态通过。上游错误原文三协议透传及写入后断网不重放工具通过。浏览器点击发送、Enter 补充发送、刷新持久化及 390px 窄屏无水平溢出通过。
