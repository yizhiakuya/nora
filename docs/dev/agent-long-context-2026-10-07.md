# 长任务上下文与证据回读

## 设计

本轮处理两个已确认的链路问题：工具在进入执行记录前就丢掉超长输出；历史装配即使仍有预算，也最多保留 40 条过程消息。继续任务时不能只保留用户要求而丢掉已完成操作的证据。

- 工具处理器负责取得结果；统一执行出口负责脱敏、输出预算和原文保存。成功、失败和结果未知共用这条路径，保留状态、图片及文件等元数据。落盘失败明确附在结果中，不伪造可回读路径，也不将已完成的操作改成可重试失败。
- 原文保存在已有工作区 `context/`，按内容哈希去重，使用现有文件读写与 `manage_workspace read` 分段回读。不增加工具、数据库表或记忆框架；这些内部记录不算用户成果。
- 轮内压缩先保留可回读记录，再缩减模型看到的正文；调用 ID、调用与结果配对、用户消息及最近工具批次保持完整。
- 历史装配按实际 token 预算选择完整消息组，取消任意 40 条限制。先压缩旧工具结果，再裁剪完整历史组；省略部分保存可回读历史，并提供有限的近期过程索引。沿用真实助手结论和工具状态，不编造“已验证”或用一次额外模型请求生成摘要。
- 用户要求仍按原文和时间顺序保留；超出模型可容纳范围时明确报错，不静默删除限制。输入预算与模型输出上限保持独立。

## 验收

使用真实模型和真实工具验证：超长输出中段信息回读、错误输出回读、运行中修改要求、不重复执行，以及跨轮继续。容量测试使用明确标注的历史填充记录与真实先前产出；透传代理只记录请求和调整测试配置，不模拟模型回答。验证压缩和裁剪后的调用配对、用户要求、回读路径、实际答案与计量。

服务重启续跑属于后续独立改动，本轮保留已有安全中断行为。

## 实测结果（2026-10-07）

最终使用 `nora-a` 的真实 `deepseek-v4.1-flash` 与 Anthropic 协议完成 34/34 项检查：

| 场景 | 实测结果 |
| --- | --- |
| 成功长输出 | 从约 16 万字符的完整记录找回中段编码；发令命令仅执行一次；运行中补充的 JSON 格式要求生效 |
| 失败长输出 | 非零退出状态保留；从错误输出的完整记录找回中段编码；未重跑发令命令 |
| 轮内压缩 | 连续工具轮次实际触发压缩；回读第一轮记录后答对；实际请求中的调用与结果 ID 完整配对 |
| 超过 40 条历史 | 使用真实种子结论和 45 条明确标注的容量填充记录；直接继续任务，保留结论与只读限制，未重读原始输入 |
| 历史预算不足 | 测试配置使用 32K 输入窗口，确实裁剪历史并提供可回读路径；从记录恢复结论与限制，未重读原始输入 |
