# Agent 状态与提交边界优化

对应 [架构审查](../reviews/agent-architecture-review-2026-10-05.md) 的四项 P2、两项 P3，已实施以下修改。

- `chatApi.applyChatStreamEvent` 统一普通 SSE 与刷新接续的消息合并、推理收尾、审批和提问清理；缓存不保存交互票据，刷新从服务端接续恢复。
- 重试先拉权威历史，再追加新轮；编辑先核对历史位置，等待服务端截断成功后再替换本地分支。失败保留编辑稿，并展示可操作的错误提示。
- 结果弹窗无草稿时自动载入新收据；有选行草稿时保留旧版本和草稿，提示载入新结果并禁用保存。保存响应优先于晚到的旧轮询；下载明确标注当前版本。
- 选行排除项、收据和产物登记沿用 Spring 数据库事务；文件写入失败会回滚数据库。旧收据不能覆盖补采后的新结果。
- Playwright actor 只负责浏览器操作与元数据快照；证据查询和文件 SHA 核验在 actor 外。默认状态只查询最新收据，`history=true` 按需查询最多 100 个历史版本；历史列表不携带完整 `expectedRows`。
- 流式 UI 仍即时更新；离线缓存每 500ms 写入一次，终态、切页和 pagehide 立即 flush，保留已有历史新鲜度与回声防护。

补测发现网关离线会卸载路由，造成草稿丢失。现在离线提示使用已安装的 Radix Dialog 覆盖页面，保持页面挂载并约束焦点；网关恢复后继续编辑。

## 验收

- 前端 typecheck、lint、120 个冒烟测试、生产构建通过；入口 JS gzip 119.47 KB。
- 后端 Spotless、145 个冒烟测试和 package 通过。
- `scripts/e2e-browser.py`：22 项真实 Chromium/API 检查通过，包括 CSV 重读、文件篡改检测、样本确认、补采、旧收据拒绝，以及真实文件写入失败后的数据库回滚。
- 真实模型依次提问两次：刷新接续第一张卡片，通过另一连接回答后第一张消失、第二张出现；停止后第二张消失。
- 弹窗打开期间真实补采：4 行自动切换为 6 行；保留 5/6 的选行草稿时收到 8 行新版，草稿不丢且保存禁用；手动载入、选行保存后，下载的 CSV 为 7 行并与核验收据一致。
- 实际暂停本地网关后，离线页面没有可交互的后台控件，编辑 textarea 仍挂载；恢复后同一编辑稿仍在。
- 外部连接追加真实模型对话后，旧编辑提交被阻止，数据库保留新增历史、界面保留编辑稿；载入最新历史后成功编辑重发，数据库和刷新后的界面均只保留新分支。

运行记录与截图见 [验收记录](../../agent-workspace/browser/agent-state-consistency-verification.json)。

## 验证边界

审批清理与失败重试已走共享规则和冒烟路径，本轮未单独制造真实审批或模型故障来验收重试。编辑覆盖了历史冲突与成功截断，未单独制造 DELETE 接口错误。轮询和缓存优化没有做长历史压力基准，不宣称具体加速倍数。

数据库事务不跨文件系统；失败可能留下未登记的版本目录，但不会发布新收据或改写当前排除项。当前改动没有新增框架或依赖。
