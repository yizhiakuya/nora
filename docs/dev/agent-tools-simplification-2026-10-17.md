# 通用 Agent 工具收敛

## 目标与现状

用户选择通用任务助手，专用工具按需提供。当前链路为 ChatOrchestrationService → ChatToolsSpec → SDK 模型请求 → ToolStepEmitter（审批、取消、步骤）→ AnnotatedTools → 领域服务。所有内置工具的完整 schema 每轮发送；浏览器、相册、数据库和配置管理的参数与长说明挤占普通任务上下文。环境查询、日志、启停和注册有四个入口，目标参数也不一致。

## 最小方案

- 文件系统、文件中心、文件交付、终端及命令等待、知识检索、技能、提问保持直接可用；增加只读 `load_tools`，随声明附上真实注册表生成的专用工具目录。模型用准确名称一次加载所需工具，下一次请求提供完整 schema，执行仍走原 SDK 与统一权限门。
- 工具选择从当前模型消息中实际保留的工具调用和成功加载回执恢复，不新增全局会话缓存或数据库状态。当前工具注册表始终是有效性边界；压缩掉相关历史后可再次加载。用户文本、外部工具文本不能充当加载回执。MCP 的既有 eager/lazy 配置保持生效，内置工具不代替远端发现机制。
- 请求的 token 估算使用实际选中的 schema，模型重试与上下文压缩共用同一选择逻辑。加载只提供契约，不执行目标工具或绕过审批。
- `manage_service` 统一 list/status/logs/start/stop/restart/register/enable/disable/remove；统一以 target 名称或 ID 定位。移除三个重复模型入口，复用原状态、日志及控制服务，保留执行结果未知、禁止盲重试和风险分级。
- 缩短工具说明，明确文件中心、工作区和交付职责；修正自动任务说明中“没有审批门”的误导。内置手册通过新增迁移更新，不改历史迁移和用户自定义技能。

影响：工具注册/装配、上下文估算、系统提示、服务工具绑定、风险与步骤展示、冒烟夹具、真实模型验收脚本、规范。HTTP 业务接口和前端状态不变；历史步骤中的旧工具名仅用于展示，不恢复旧执行入口。

## 验收与恢复

执行 Maven verify；隔离数据库和工作区下验证普通文件任务、按需加载后执行专用工具、服务状态/日志、控制审批拒绝与取消、非法加载名称与无效参数。记录实际 schema 数量和大小，不能把输入缩减等同于推理速度提升。迁移只更新内置手册的旧工具指引；回退时恢复应用版本，并根据备份恢复该手册正文，不删除 Flyway 历史或用户数据。

## 实际结果

- `mvn verify` 通过：301 条冒烟，0 失败、0 错误；Spotless 与打包通过。
- 不挂载 eager MCP 的测试注册表共有 19 个内置工具，普通请求提供 9 个。按 `ToolSpecification.toJson()` 求和，初始声明 7,675 字符，全部声明 21,435 字符，减少约 64%。这是本次实现内部的声明体积比较，不是耗时或 token 的实测提升；eager MCP 仍按用户配置注入。
- 隔离 PostgreSQL 数据库、工作区、文件目录及测试容器，使用真实 `deepseek-v4.1-flash`：`catalog`、`annotated`、`builtins`、`standards` 全部通过。自然任务自行加载服务工具，后续复用；状态/日志与落库结果一致；非法名称失败；批准、拒绝、取消和未知结果均保持原权限语义；文件、技能与交付链路保留真实副作用检查。
- 对隔离 JVM 执行重启后，同一会话继续查询服务，持久化步骤确认不重复调用 `load_tools`。验收脚本曾将历史接口的数组响应误当信封，修正读取方式后核对同一次运行记录通过，未重发业务操作。
- 新隔离数据库启动前需按部署前置条件启用 `vector` 扩展；首次准备遗漏已补齐，未更改历史迁移。验收明细位于本地忽略目录 `logs/tools-acceptance-20261017/`，Maven 日志为 `logs/agent-tools-verify.log`。
- 本次未修改前端，未重复执行前端构建或浏览器 UI 套件。未实测所有模型和全部专用工具；首次使用专用能力通常增加一次加载往返，历史压缩丢弃相关调用后可能需要重新加载。
