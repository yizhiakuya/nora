# 聊天缓存配额修复

## 原因与链路

线上会话 `sess-1791600024701` 的前端日志确认：`chat-sessions` 写入 localStorage 时抛出 `QuotaExceededError`，经 `saveMessages` / `saveComposerDraft` 的 effect 传播到页面错误边界；新建会话也会失败。Zustand persist 默认序列化完整 store，包含所有已查看会话的正文、思考、工具输出及图片结果。500ms 的流式回写重复序列化全部历史，后端已有完整消息持久化，浏览器又保存一份无界历史没有必要。

## 最小方案

- 后端继续作为消息历史的唯一持久化来源；`saveMessages` 保留当前页面的会话内存缓存和已有历史新鲜度机制，切换会话/恢复运行仍走现有链路。
- `chat-sessions` 只持久化会话索引、选中会话、输入草稿和未发送队列；完整 messages 不落 localStorage，不保留第二套离线历史。
- 提升缓存版本到 v2，自动移除旧版本缓存中的 messages，保留草稿、引用、队列、暂停状态与当前会话。服务端数据不变。
- 在同一个存储边界处理明确的浏览器配额/访问限制异常，保留当前页面状态并显示原始错误与草稿持久化失败提示；其他程序错误继续抛出。不清空浏览器其他数据、不截断用户输入。

## 验证范围

缓存迁移、超大工具/消息内存缓存、草稿和队列刷新恢复、配额失败时页面仍可工作；线上原会话历史正常打开。前端四项质量门，发布仅更新 Web，Agent 保持运行。
