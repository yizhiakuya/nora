# 代码质量清理（2026-10-11）

## 范围与设计

覆盖 Nora 主仓的 Java 服务、React 前端、构建和当前维护文档。手机相册 MCP 是独立仓库；运行数据、工作区记忆、数据库迁移和历史验收材料不作为死代码删除。

先核实真实入口、调用方、测试、构建和配置，再删除或替换。已有未提交改动保留；本轮开始时的源码快照和检查日志在本机 `logs/code-quality-20261011/`（不入库）。知识图谱工具本轮不可用，采用全仓源码和配置引用检查，结论不等同于完整静态证明。

职责边界：Spring/JDK/现有依赖负责通用协议、解析和编码；Nora 保留权限、资源范围、持久化与业务结果。新依赖必须能删除一整类自维护实现，且验证实际行为；不为几行工具代码增加依赖，不因清理改动大版本框架。

## 已确认的问题与最小方案

| 问题 | 影响 | 方案与完整链路 |
|---|---|---|
| `nora-security` 没有被任何服务依赖，JWT 过滤器没有注册入口 | 无效模块仍编译并维护 Spring Security/JJWT；文档暗示了不存在的认证方式 | 删除模块、父 POM、Dockerfile 和启动脚本中的构建项；实际入口仍为 gateway 的单用户令牌鉴权 |
| API 包保留已删除 RPC 服务的请求/统计 DTO | 测试只构造这些类型，实际 HTTP 控制器没有使用；Javadoc 指向不存在的服务 | 删除无生产消费者的 DTO 及对应冒烟路径，保留真实共用响应契约 |
| `next/dynamic` 与 `next-themes` 别名和手写 shim 残留 | React SPA 仍维护旧框架兼容层，类型退化为 `any` | Markdown 改用 React `lazy`/`Suspense`；主题直接引用现有 ThemeProvider；同步清理 Vite、TS、Vitest 和规约 |
| 前端未使用组件、导出与开发依赖没有持续检查 | 旧首页、文件视图与重复组件继续占用维护面 | 删除无入口实现、Faker 和旧样式脚本；内部符号取消导出，Radix 保留实际使用的组件；增加 Knip 开发依赖与 CI 检查 |
| `.env.local` 手写逐行解析 | 引号、注释和多行值需要自行维护 | 已核对 `dotenv-java` 3.2.0 官方实现，其 export/BOM/单引号行为不满足现有契约，本轮保留解析器，不叠兼容处理强行接入 |
| 下载响应手动拼接 Content-Disposition | 重复 URL 编码，响应头维护分散 | 使用已有 Spring `ContentDisposition`，覆盖所有下载入口及 UTF-8 文件名 |
| ProxySupport 保留无调用入口 | 没有消费者的代理选择器与占位方法增加维护面 | 删除死入口，保留实际调用的代理地址策略 |
| 数据库读写被多层守卫及重复工具拆开 | 不符合当前个人终端智能体的业务定位；Agent/服务重复检查并维护两份 Redis 白名单 | 按用户 2026-10-11 指示删除 SqlGuard/WriteGuard/RedisGuard、连接只读配置和 execute_write_sql；统一 execute_sql 与服务执行入口，SQL 支持批次/RETURNING，Redis 复用 Lettuce 原生命令分发；刚引入的 JSqlParser 同步撤掉 |
| 数据源目标可能退回第一个连接，且写入失败语义不明确 | 名称错误或重名可能操作错误数据库；响应丢失后重发可能重复写入 | ID 优先精确匹配，名称必须唯一，多个连接时禁止省略目标；请求结果不确定时沿工具结果传递 outcomeUnknown，先核对再决定是否重试 |
| 恰好 200 行结果也被标为截断 | 模型与界面会把完整结果误报为部分结果 | JDBC 多读一行作判断，仍只展示 200 行；真实验收覆盖 199、200、250 行 |
| 日程解析使用 SMART 时间格式和重复兜底 | `24:00` 被转换为午夜，重复格式掩盖非法输入 | JDK 严格格式一次解析，异常只捕获日期时间错误；非法日程仍由 API 返回 400 |
| 业务异常分类与捕获分散 | 技能更新把非法名称误报为 404；唯一键冲突在控制器重复处理，其他入口缺少统一 409 | 校验和未找到分类放到服务层，公共层处理 DuplicateKeyException；删除控制器重复捕获，保留 400/404/409 语义且不暴露 SQL 细节 |

## 实施与验收

本轮相对开始时的源码快照，主业务 Java/TypeScript/TSX 净减少 **1,835 行**，删除 **16 个生产源码文件**。统计不含测试、文档、SQL 迁移、锁文件和独立手机 MCP 仓库；不是相对 Git HEAD 的统计，避免把此前未提交改动算入本轮。

数据库能力现在只有一条执行链路：`execute_sql → SqlToolClient → DatasourceServiceImpl.execute → JDBC / Lettuce`。保留 query/execute 两个既有 HTTP 路由，两者指向同一个服务方法，不再维护重复写入实现。SQL 支持原生批次、DDL/DML、RETURNING 和写 CTE；Redis 不再使用自维护命令白名单或 RESP 转换器。SQL 与终端命令一样按会话权限模式执行，FULL 自动，ASSIST/ASK 询问；连接超时、SQL 30 秒执行超时和 200 行展示上限仍用于资源管理。

同步清理工具声明、分发、构造器、风险分类、审批展示、自动任务调用和开发说明。V42 迁移只替换已存在内置手册中的旧数据库指引，保留其他正文和用户配置；历史 Flyway 文件不改校验和。前端仅在历史工具行展示中保留旧工具名称识别，不再注册该工具。

## 依赖取舍与未覆盖范围

- 通用能力优先复用现有 Spring/JDK/Lettuce：下载响应头交给 ContentDisposition，Redis 分发与解码交给 Lettuce，严格时间解析交给 JDK。公共异常层使用 Boot 管理的 spring-tx 类型识别唯一键冲突。
- dotenv-java 不能等价覆盖当前 `.env.local` 契约，保留现有小解析器；不添加兼容层。SQL 不再限制只读，因此不保留 JSqlParser。LangChain4j、MCP SDK、CSV、浏览器已有标准依赖，业务编排不因“手写”二字被替换。
- 保留 Spring Boot BOM 的既有优先级，不顺带升级主要框架。Java 反射入口不凭文本引用次数删除；本轮没有完整知识图谱覆盖证明。
- 未对真实模型付费调用、MySQL 实例、Linux 部署和生产负载做复验。本轮没有发布到 megumin，也没有提交或推送 Git；线上配置和数据没有被本轮测试修改。
