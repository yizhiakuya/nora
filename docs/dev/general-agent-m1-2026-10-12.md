# 通用 Agent 产品化：M1 实施

依据：`../research/nora-general-agent-product-design-2026-10-12.md`。本批完成任务入口、历史找回、运行跟进和成果入口；M2–M4 涉及运行协议的部分另行设计验收，M5 按需求启动。

## 修改前设计

- 延用 `chat_session`、`chat_run`、`saved_artifact`，不新增任务状态表或第二套执行器。
- 历史页服务端按标题、ID、消息正文检索，分页每页 30 条，多取一条判断后续页。稳定排序包含 ID；软删除消息与会话不参与搜索。保留侧栏现有全量同步契约，避免把分页缺席误判成删除。后续海量索引优化需要单独迁移同步协议。
- 独立会话详情接口用于深链接；指定会话未找到时显示原始错误，禁止回退到其他会话。打开前加载元数据到已有会话 store，保留草稿和队列。
- 快速查找接入同一后端会话搜索；文件打开现有 viewer，知识文档打开其详情。保留现有数据源、环境导航。
- 运行列表和最近结果定时刷新，页面隐藏时暂停，重新聚焦立即刷新；刷新失败保留上次数据并显示错误与重试，不伪装空态。
- 待处理项读取当前 ApprovalService/QuestionService 中未结算的有效请求。列表只提供回到原会话处理的入口，不复制票据状态或另建审批机制。
- 首页最近运行覆盖普通与自动会话，已保存成果独立显示，失败和部分完成明确区分。成果只声称已登记文件，不把任务成功等同于文件成果。
- 输入区常驻显示执行环境、系统、项目目录；项目仍是可选上下文。现有绑定接口已调用 ensureSession，支持首条消息前配置。
- 实测发现项目绑定/排队提前创建会话时，旧代码以 INSERT 是否成功判断首轮，导致不生成标题。改为首次用户消息前、尚无消息且未生成标题时初始化；自动任务固定标题保持原协议。

## 影响范围与验证

后端：会话查询服务与控制器、有效待处理项读取；无数据库迁移。前端：API、会话 store、历史路由、侧栏、快速查找、首页、运行列表、项目按钮与知识详情深链接。复用现有组件和服务，无新依赖。

验证：后端 Maven verify，前端 typecheck/lint/deadcode/test/build；真实 HTTP 创建独立测试会话验证分页、正文搜索、删除过滤和未知会话；浏览器验证历史深链、刷新、搜索、响应式与错误态。待处理项的审批/提问协议沿用现有测试，新增读取冒烟覆盖。

## 实施结果

2026-10-13：M1 已完成并通过本地验收。

### 已交付

- 新增「全部会话」：服务端搜索标题、ID、消息正文，每页 30 条；支持 URL 保留检索条件、翻页和指定会话直达。
- 快速查找接入会话正文搜索，支持键盘选择；文件命中打开预览，知识文档命中打开指定详情，刷新保留定位。
- 首页持续显示运行、待回答和待批准入口；处理后自动更新。最近运行包含普通会话与自动任务，已保存成果独立展示并可打开。
- 首页和会话输入区显示执行环境、系统与项目目录；绑定失败保留真实错误和重试入口。
- 修复提前绑定项目或排队创建会话后，首轮不生成标题的问题；后续轮次保留既有标题。
- 指定会话不存在时显示错误与重试，不会误打开另一条会话。

### 边界与后续

- 本批完成 M1；M2 的运行控制与必要输入持久化、M3 的验证交付、M4 的长期复用仍按研究文档推进，M5 按需求启动。
- 待处理概览复用当前运行内存中的请求，不承诺服务重启后恢复待回答或待批准；持久化与恢复协议属于 M2。
- 会话搜索采用数据库字面子串匹配，尚未做海量历史压测；侧栏仍沿用现有全量同步协议。实时新增消息可能改变翻页期间的排序。
- 快速查找的会话搜索覆盖服务端历史；资料搜索仍限于当前已载入资料，界面已明确标注范围。
- 本次没有部署到正式服务；保留仓库原有未提交改动，没有进行整仓提交。
