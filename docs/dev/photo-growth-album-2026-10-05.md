# 照片成长相册

把真实照片选片、风格反馈与增量更新接成一个可重复使用的 Agent 流程。

## 用户入口与交付

首页「照片成长相册」预填需求，用户补充主体和时间范围后发送。Agent 先读取同名技能，使用已经连接的手机相册 MCP 或用户提供的图片检索、扫图和选片。图片必须真正查看过，日期必须来自工具元数据；不能虚构年龄、身体变化或拍摄日期。

新增 `manage_photo_album`：list / read / create / update / feedback。选片使用现有 workspace: / file: / media: 文件引用；手机照片先经 fetch_media 的 items 下载已选真实 URL，再逐张读取落盘图片核对文案。拼图只用于粗筛。工具负责校验图片、内容哈希去重、时间排序、持久化清单和生成自包含 HTML，视觉判断仍由模型承担。

生成后调用 open_file(intent=deliver)，沿用统一文件查看器和已保存成果。相册无需外部图片地址、脚本或第三方 CDN，下载后也能打开。生成预览图不改源照片。布局与主题类放在内层相册容器，兼容查看器 HTML 清理时移除 body 属性的行为。

## 状态与更新

- `photo-albums/<album>/album.json` 保存主体描述、选片来源、日期、文案、样式、版本和反馈。album 是 1–64 位小写英文/数字/连字符标识，固定存放于工作区内。
- 每版交付 `v<revision>.html`，旧版仍可打开。图片预览按源内容 SHA-256 保存，重复输入不增加照片。
- update / feedback 必须传 read 返回的 revision；旧版本写入返回 409，避免两个对话互相覆盖。
- 先验证全部输入并渲染，再保存版本文件、最后原子提交相册清单。输入验证或渲染失败不改变当前清单。
- feedback 保存用户原话以及明确指定的主题、布局、文案语气；remember=true 仅在用户明确要求今后沿用时使用，将偏好保存为工作区文件，供新相册继承。反馈记录不是模型训练。
- 增量更新由用户再次提出需求，或由用户明确创建的现有定期任务触发；本功能不新增后台监听器。

## 范围与权限

只处理可解码的 JPEG / PNG / GIF 静态预览，最多 24 张代表照片；预览缩放并内嵌，HTML 必须在现有 2MiB 文本查看上限内。列表/读取及固定区内生成与反馈均为 LOW，与现有工作区写入一致；读取手机相册仍遵守原 MCP 权限。任意 URL、区外引用、未知动作、无效日期、坏图片、旧 revision 均拒绝。

HTTP API 位于 `/api/workspace/photo-albums`，与 Agent 工具共用服务，复用工作区网关路由。

真实验收同时修复了两处既有链路问题：chat.completions 中转会忽略工具结果内的图片，现在将图片作为同批工具结果之后的 user 附件发送；fetch_media 接上已有 downloadItems，并拒绝只有 folder/type 的未限定下载。整库备份须明确传 all=true，范围下载仍支持 album/from/to，选片优先 items。

## 验收

单测仅执行创建、读取、增量、重复、反馈和偏好继承路径，不写断言。真实服务 E2E 检查版本、去重、继承、旧版本拒绝、输入失败无变更、HTML 转义与图片加载；浏览器检查首页入口与统一查看器；至少一次真实模型工具调用验证技能读取、相册工具和 open_file 交付。
