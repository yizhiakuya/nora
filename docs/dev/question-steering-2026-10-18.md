# 提问等待期间插入请求

问题：`ask_user` 阻塞等待答案；插入入口将请求持久化并放入 LiveTurn，但编排仅在下一轮读取输入，导致必须等原问题超时。前端已按插入边界分段，因此同时显示旧问题和新段的“正在思考”。

方案：LiveTurn 为当前未消费输入维护一个完成信号，成功持久化并发布插入事件后唤醒。ask_user 同时等待答案和该信号；新输入胜出时结束提问，返回“用户已插入新请求，原问题尚未作答”，再由原编排消费完整内容及引用。不伪造回答，不取消整个 Run，不自动批准审批。仅排队不会唤醒；消费输入时重置信号，后续提问仍正常等待。

职责与竞态：信号在 LiveTurn 锁内读取、完成和重置，覆盖插入先于提问注册的窗口。提问 future 由 QuestionService 收尾，旧 token 失效；现有工具终态事件清除实时快照及前端问题卡。直接 steer 与队列 insert 共用 enqueueInput，重试沿用既有幂等持久化。无需新增持久化状态、SSE 类型或前端补丁。

影响：TurnStreamRegistry、QuestionService、QuestionTools、构造夹具、相关冒烟；真实 HTTP/模型验收覆盖普通排队、两种插入入口、重复插入、旧票据、引用内容、再次提问和取消。原 core 队列验收改为不再回答已被插入取代的旧问题。
