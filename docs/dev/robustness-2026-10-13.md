# 状态与请求链路加固

## 范围与设计

本轮从公共请求层、任务管理和聊天成果保存切入，修正已确认的竞态与错误处理问题。保留既有后端接口和 UI，不引入第二套状态管理。

- 自动任务：创建和启停仅接纳后端返回的规则；运行与重试共用同一入口和按规则 ID 的运行状态。同步响应必须仍是最新请求，且没有被后续写入结果取代，才能更新列表。等待状态不持久化，取消固定三秒的重试等待。
- 触发方式：入口显式传递 manual/daily/weekly，不再从中文显示标签反推业务类型。
- 请求层：自动任务运行记录及计划状态实时读取；HeadersInit 统一用平台 Headers 处理，避免 Headers/元组形式丢失；带自定义请求头的 GET 不共享仅按路径索引的缓存。
- 成果保存：从消息渲染中抽离独立保存组件，补齐保存中的禁用状态；归属登记失败明确提示，保留已成功保存的成果，不把登记失败误报为保存失败。
- 知识库按名称更新内容，因此新保存文档的名称追加既有内容键，避免不同回答前 24 字相同时覆盖旧文档；消息内容变化时重新初始化对应的保存按钮。
- 执行通知由服务端发布，客户端同步结果并保留原有浏览器通知，不再重复写入同一事件。

涉及调用点：任务页、历史重试、新建任务弹窗、日志诊断、SQL 查询保存、聊天回答操作区；接口均复用既有服务层。后端已返回完整启停结果，并对运行中的同一规则做互斥，本轮先修正客户端没有消费这些契约的问题。

## 验证

已通过：

- `pnpm typecheck`、`pnpm lint`、`pnpm deadcode`。
- `pnpm test`：40 个文件、156 项冒烟通过；新增任务并发/失败/旧响应、请求头、保存失败与登记失败路径。单元测试不含新增断言。
- `pnpm build`：生产构建成功，入口 gzip 124.81 KB；既有 useChatSessions 同时静态/动态导入的提示仍存在。
- `node scripts/e2e-robustness-client.mjs`：18 项真实服务检查通过。使用当前前端源码编译后的 store/服务层连接本地后端、真实模型；JSDOM 仅提供独立的存储环境，没有模拟业务响应。验证创建失败、并发启停、迟到同步、重复运行、超过三秒等待、真实重试、记录去重、瞬态不持久化、请求头透传及登记错误。延迟用真实 HTTP 结果交付门控制。
- 生产预览 HTTP 检查：首页、任务历史、聊天和设置路由及其 JS/CSS 产物均可访问。

验收脚本使用 `NORA_E2E_BASE_URL`（默认 18080）和 `NORA_AUTH_TOKEN`，不写入凭据。临时手动规则和会话已删除；服务端软删除的执行历史及验收通知按原有审计机制保留。脚本只要求模型回复固定确认，不请求工具操作。

## 验证边界

本轮是公共请求、自动任务和成果保存链路的专项加固，没有宣称完成全仓库逐行审计。未改后端代码、未重跑 Maven 全套测试；未验证多实例并发。浏览器工具因 URL 安全策略拒绝访问，未进行本轮真实浏览器点击和视觉回归，生产预览只完成 HTTP 检查。知识库保存按钮覆盖了冒烟路径，真实服务验收主要覆盖任务及登记契约，未将其算作知识索引完整链路验收。
