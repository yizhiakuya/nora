# 旧会话中的目标范围与轮次终态

## 证据与根因

`sess-1791592446888` 在输出边界修复后的第二轮仍耗时 285.5 秒并被取消，其中思考 270.2 秒，工具耗时合计 7.1 秒；之后“继续”在 17.4 秒内给出结果。未再次发生 NUL 保存失败，但它反复检查本机和 megumin，三次把 SSH 的毫秒超时填为 60/30。

- 本机现有 SOUL/AGENTS 仍是旧的“工作台操作员”版本。初始化只补缺失文件，所以更新源码中的默认模板不会修改已有指令；线上旧身份曾已修改，本机没有同步。
- 历史消息 DTO 已有 runStatus，但上下文重建只发送工具往返和答案，没有传入 partial/cancelled/interrupted/failed 终态。旧轮次无最终文本时，模型容易把工具历史当成还需要继续核实的任务。
- MCP 的 ssh_exec 原始 schema 明确写了 milliseconds，Nora 与 LangChain4j 直接透传。错误属于模型参数选择；不能通过猜数值、改单位或偷偷重试掩盖。
- 上一轮输出修复的 E2E 使用 none 档，覆盖了实际输出与数据持久化，未覆盖用户 max 档和这段失败历史下的决策行为。

## 最小方案与边界

- 沿既有历史重建链路传入失败/取消等已结束状态，明确旧工具步骤是执行证据。保持原始用户要求、步骤和结果，不重放命令、不改旧会话。
- 在既有基础协议中明确：任务范围来自用户指令，历史助手涉及多个环境不表示用户要求都查；有多个目标且不能确定时提问，确定后只查目标。概况查询有直接资源/进程证据即可回答；无额外排障要求不追溯启动脚本、源码或陈旧错误。
- 可选超时无特殊需求时省略，使用工具默认值；必须设置时遵守 schema 单位。MCP schema、名称、调用参数与上游默认值保持一致，不做隐式秒/毫秒转换。
- 本机引导文件定点更新旧身份段落，备份原文，保留用户画像、记忆和文件组织约定。默认模板采用相同事实与范围规则，未来工作区直接使用。
- 用当前模型、中转与 max 档验证原始简单请求及带真实失败历史的独立副本；读取真实 SSE、模型工具参数和持久化回答。此前 none 档验收只作为数据链路证据，不当作决策性能保证。

不新增任务分类器、工具适配器、自动重试、轮数硬截断或降低用户思考档位。实际模型仍可能花较长时间推理，本次验证的是范围、契约与收尾行为。

## 本地复测记录

- 首次带真实失败历史、max 档的模糊请求耗时 143.8 秒，仍查两台主机并两次误填 SSH 超时，未通过范围与契约验收。这一结果不能作为部署通过的证据。
- 结束状态最初置于历史工具链前，后面的工具往返仍像尚未收尾。改为在该轮全部工具结果及答案之后附结束状态，同时覆盖 completed 和失败/取消等终态；压缩摘要也复用同一历史装配入口。
- 第二次同一模糊请求耗时 89.7 秒，其中推理 80.3 秒、工具 5.0 秒；没有超时或保存错误，仍自行查询两台主机，范围验收未通过。不能据此保证模糊请求会先提问，亦不能保证 max 档的推理时延。
- 验收脚本原先每个推理分片都重写完整 JSON 报告，拖慢了客户端读完 SSE。改为仅记录步骤和问题事件，并按正常网络块读取；本例服务端耗时与客户端耗时已一致。该问题仅在验收脚本，不是产品性能修复。
- 保留 `task-scope` 对原始模糊请求的严格验收；另以 `task-target` 检查用户明确指定 megumin 时，带旧历史与新会话是否都遵守目标。不用后一项通过覆盖前一项失败。

## 实际限制

模糊目标的旧会话仍会自行查询两台主机，尚未达到稳定先提问的行为；max 档仍可能长时间思考。明确目标的 20/12 秒不是对原始模糊请求的性能保证。MCP 参数契约没有改写或自动换算，模型偶发误填仍必须如实暴露，不能靠隐式重试隐藏。
