# 规范检查修复（2026-10-15）

范围：本轮审查的下载完整性、命令终态保存、文档切换竞态、服务端列表状态、通知写入、模型探测、登录存储与测试分层。

## 设计

- 批量下载先核对全部 ID 和文件可读性，再写响应；传输失败向上传播，不跳过文件或吞异常。
- 命令继续由 TerminalService 拥有进程，CommandExecutionStore 拥有持久化。终态先写工作区 `.runtime/command-finalizations` 日志，再幂等落库，成功后才完成等待和发布完成事件。失败只重试保存，绝不重放命令；启动先恢复日志，再将真正失联的旧进程标为 unknown。沿用会话终态日志的原子写入模式，无数据库迁移。
- 前端业务列表只驻留内存；模型选择和环境选中项仍可持久化。移除旧缓存中的业务快照，保留允许的偏好；读取失败留存内存旧数据并显示错误与重试，首次加载单独展示。
- 文档分段写入绑定详情生命周期，切换/关闭后忽略迟到的界面更新；后端写入不因切页而取消。同名文档以服务端身份区分。
- 通知列表以服务端为准；批量写操作等待成功且防重复，读响应不能覆盖较新的写入。失败展示错误，未知结果仅重新查询。
- 模型列表要求有效 JSON 和 data 数组；合法空数组可成功，畸形响应失败。登录只有令牌成功保存后才跳转，存储失败原样展示。
- 单元测试执行并等待实际代码路径；真实 HTTP/浏览器验收核对结果，测试模拟调用序列不再标为 E2E。
- 压力验收发现脱敏表达式在长串普通文本中逐字符回溯，导致输出读取超时；限定凭据键的起始边界，保留原有脱敏范围。
