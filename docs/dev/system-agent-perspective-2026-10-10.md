# Agent 执行视角修正

## 问题与证据

`sess-1791612790023` 的要求是「看下我gh仓库」。前 20 个模型轮次主要搜索工作区归档、浏览器缓存和历史记录，第 21 轮才检查 gh，第 23 轮开始直接获取账号和仓库。当前基础提示和 SOUL.md 都将 Nora 定义成工作台操作员，终端描述又把探索范围限定在工作台/项目内。工作区被描述成「家目录」，实际 CLI 用户目录却是另一个路径。

megumin 宿主机有已登录的 gh；Agent 容器有先前安装的 `/app/data/tools/bin/gh` 和 `/app/data/tools/gh-config`，但未注册到默认命令环境。每次手动 export 才能使用。运行环境摘要仅检查 Java 进程 PATH，遗漏命令执行层注入的用户环境变量，也没有检查 gh。这些问题共同鼓励了错误的探索路线，不能仅归因于模型。

## 最小方案

- 基础提示定义系统执行智能体身份，工作台是交互入口；按任务使用当前系统中的工具、账号和项目，历史资料仅在确有需要时回读。
- 默认 SOUL/AGENTS 和工作区引导采用相同定位。工作区是默认任务目录和成果存储，不能等同于登录用户主目录或宿主机根目录。保留用户的「不自动记录」设置。
- 直接任务优先使用相关的专用工具或 CLI 的身份、状态、查询命令；授权和账号仍不明确时向用户询问。简短查询不强制创建报告。没有增加任务分类器、路由层或 GitHub 专用逻辑。
- 命令环境摘要使用与进程执行相同的环境变量来源，复用命令解析器；显示 gh/ssh、真实用户目录和容器边界。摘要不主动联网或提取令牌。
- 将线上已有 gh 的 PATH、GH_CONFIG_DIR 写入既有环境变量设置，定点修改已有 SOUL/AGENTS 的旧身份段落。保留密钥、会话、记忆和其他用户约定。

## 边界与验证

Agent 命令仍在 nora-agent 容器中执行；改变身份提示不授予 megumin 宿主机 root 权限。系统视角必须以工具实际执行域为准，不能将容器查询结果当成宿主机事实。宿主机通用执行能力需要单独设计执行连接，本次不添加隐式 SSH 或挂载 root 配置。

检查调用链、单元冒烟、真实模型「看下我gh仓库」和环境来源验收。检查已保存账号、直接 CLI 查询、没有无关历史/浏览器搜索、没有创建不需要的报告，以及运行快照与真实命令的一致性。仅发布 Agent 服务，保留其他服务。
