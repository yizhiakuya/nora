# 网页资料任务：入口、样本、进度与结果调整

## 用户流程

首页「网页资料收集」打开任务表单，填写网址、目标、必需字段和数量。场景按钮预填文章整理、产品对比、名单采集；官方文档体验示例单独提供，点击后填入表单，不直接发起固定演示。

表单先在服务端创建冻结字段与数量的计划，再进入真实会话自动发送用户任务。默认先采至多三条样本，服务端在用户决定继续前禁止全量采集和导出。样本方向不对时可补充要求重新采样；确认后继续真实采集。直接在聊天中发起、没有选择先看样本的旧流程保持可用。

对话上方显示任务目标、字段、实际已采集和有效数量、样本待确认、人工接管、结果待检查或完成状态。沿用既有会话和 Agent 执行链路，不增加第二套任务执行器；浏览器由用户选择展开，窄窗口不自动遮住任务与对话。

结果表格保留来源，可分页查看、取消不需要的行、去除完全重复的行，再保存为新 CSV 版本。选中行只使用真实采集记录 ID，不能输入任意数据绕过采集。人工排除的内容保存在本次计划中，补采导出时仍排除；缺少必需字段或数量不足如实显示，并可以把补采要求发给当前对话。下载使用现有带鉴权的文件下载入口，成果进入已有成果列表。

## 实现边界

- 扩展 `browser_evidence` 的计划元数据，不改变已冻结的字段与最低数量，不修改已应用迁移。新增迁移只更新工作流技能与手册。
- `BrowserTaskService` 负责样本决定、任务摘要、表格分页与调整；`BrowserEvidenceService` 继续负责原始采集证据、CSV 写入与实际文件核验。
- UI 任务 API 的样本确认和重新采样仅允许直接用户调用；Agent 可读取任务和真实行，不能自行确认样本。浏览器接管规则继续生效。
- 前端复用现有 Modal、Radix Checkbox、Input、Button、聊天发送与文件查看/下载服务。新表单和结果弹窗按需加载。
- 第一轮调整支持选行、去重和补采，不开放直接修改网页原始值。模板和定期变化对比放在后续轮次。

## 验收

真实 API 验证样本上限、未确认导出拒绝、重新采样隔离、确认后采集、结果分页、选择 ID 校验、调整版本来源、最低数量不降低、排除项在补采后继续生效、重复与缺失检查和跨会话拒绝。

真实模型与 Nora UI 验证：任务表单 → 三条样本 → 人工继续 → 全量表格 → 排除一条 → 不足提示 → 补采 → 新版本下载。任务状态在刷新后仍能正确显示。

执行后端冒烟测试、Spotless、前端 typecheck/lint/test/build。单测无断言；行为判断由真实服务和浏览器 E2E 承担。

## 对话执行时间线

沿用现有「模型调用 → 工具执行 → 回填结果 → 下一轮模型调用」循环。正文 SSE 增量携带 roundIndex，首次正文 token 即在既有 steps 中占位，轮次结束后标记为 commentary（继续调用工具）或 answer（最终回答）。进度说明与工具按真实事件顺序显示和保存，不再把全部中间说明拼到末尾。停止或失败保留已输出的说明；普通 SSE、接续 SSE 和刷新历史使用同一轮次顺序。

模型协议要求每轮工具前给简短的当前发现与下一步原因，收到结果后再决定依赖操作，出错时说明调整。展示面向用户的工作进度，不要求输出内部推理全文。既有 reasoning_delta 仍按模型实际返回处理，没有推理字段的模型也能展示真实进度说明。

`scripts/e2e-browser-agent.py --flow-only` 使用真实模型、真实网页和错误选择器，验证进度说明与工具交错、失败后的调整、原计划成果、流式正文与轮次终态一致、刷新顺序不变以及最终回答独立保存。
