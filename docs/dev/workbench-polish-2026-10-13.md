# 工作台视觉与交互统一

需求：继续现有暖灰、简约桌面工具风格，覆盖整个工作台；不改变任务执行、模型权限或存储协议。

现状链路：各页面通过 Header 提供面包屑与页面操作，再渲染 page-content/page-heading/Tabs；会话通过 ChatConversation → ChatInputArea 与 ChatMessageItem 展示输入和结果。NotificationBell 直接使用 div 作为菜单触发器，缺少按钮语义。工作区按钮复用 SessionProjectDialog，路径来自服务端。

最小方案：统一公共标题、滚动和空态；Header 将页面操作与全局操作分组，窄容器下页面操作独占第二行，避免标题和图标挤在一起。通知入口改为标准 Button，面板沿用 Radix 和真实通知数据。输入框聚焦改用克制的中性边框，工具按钮只保留自身焦点环；窄屏保留可截断的模型名。工作区显示目录名称，完整路径在悬停及选择器保留；消息复制与保存合并到同一操作行，使用公共按钮，保留原事件和错误处理。

范围：公共 CSS、Header、NotificationBell、EmptyState、资料搜索入口、会话输入与消息操作、SessionProjectButton。图谱工具当前不可用，按相关源码与引用检查。不改后端、不添加依赖、不改变保存/通知业务行为。

巡检补充：AutomationList 的独立卡片内再套触发/动作卡片，占用大量纵向空间。改为单一列表表面和分隔行，完整保留任务名称、状态、需配置提示、触发/动作文本、上下次时间、开关与运行入口；空列表复用 EmptyState。数据仍由 useAutomations 提供，运行与切换函数原样保留。

验证：前端质量门；真实浏览器巡检首页、会话、资料、任务、数据源、环境、Agent、设置；通知键盘开关、工作区选择器、模型菜单、390px 布局；生产预览后恢复开发服务。业务写操作只检查入口，不为视觉验收更改配置或创建外部任务。
