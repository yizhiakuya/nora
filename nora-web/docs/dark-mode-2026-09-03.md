# 暗色模式收口 · 验证记录（2026-09-03）

> 状态：已完成并视觉验收 · 范围：全站暗色主题适配（纯前端，无后端改动）

## 1. 修复前问题

应用有主题切换入口（设置 → 通用 → 深色模式），`ThemeProvider`（next-themes，class 策略）与 CSS 变量 token 已就位，但全站 46 个组件文件中存在 **560 组硬编码浅色工具类**（`bg-white` / `bg-[#f4f5f7]` / `text-gray-800` / `border-gray-200` / `bg-blue-50` 等）没有 `dark:` 变体。切到暗色后出现大面积"半黑半白"撕裂：白色卡片、浅灰表格、浅色徽章全部保持亮色。

## 2. 修复策略

**只追加 `dark:` 变体，浅色模式像素级不变。** 禁止改动任何浅色类名本身。

映射规则集中在幂等脚本 `scripts/apply-dark-variants.ps1`（可重复执行；同属性已有 dark 变体时自动跳过）。核心映射：

| 类别 | 浅色 | 暗色 |
|------|------|------|
| 页面底色 | `bg-[#f4f5f7]` | `dark:bg-gray-950` |
| 卡片/表面 | `bg-white` / `bg-gray-50/100/200` | `dark:bg-gray-900` / `dark:bg-gray-800` |
| 文字层级 | `gray-900→400` | 逐级反转 `gray-50→500` |
| 边框 | `border-gray-100/200/300` | `dark:border-gray-800/800/700` |
| 主按钮 | `bg-blue-600` / `hover:bg-blue-700` | `dark:bg-blue-500` / `dark:hover:bg-blue-600` |
| 彩色徽章 | `bg-{hue}-50` / `bg-{hue}-100` | `dark:bg-{hue}-950/40` / `dark:bg-{hue}-900/50`（hue: blue/red/green/yellow/purple/orange） |
| 彩色文字 | `text-{hue}-500/600/700` | `dark:text-{hue}-400` |
| 渐变淡出 | `from-[#f4f5f7]`（对话输入区） | `dark:from-gray-950 dark:via-gray-950` |

**刻意不改**（两种主题下本就正确）：
- `bg-[#1e1e1e]` + `border-gray-800` 常暗代码编辑器（4 处，含编辑器内 `text-gray-300` 浅字——已从批量结果中手动还原）
- `text-white` / `border-white`（彩色表面上的前景）
- `bg-black/40`、`bg-black/50`（弹窗遮罩，暗色下天然成立）
- `from-blue-500 to-indigo-600` 头像渐变、`bg-blue-500/red-500/green-500` 状态点
- `focus/ring-blue-500` 焦点环

## 3. 过程事件（含一次事故与恢复）

1. **编码事故**：首轮注入脚本在 Windows PowerShell 5.1 下按 ANSI 读取无 BOM 的 UTF-8 源文件，46 个文件的中文字符串被二次编码为乱码。**通过基线提交 `git checkout -- .` 完整恢复**，脚本改为显式 `UTF8Encoding(false)` 读写后重跑成功。此事故验证了版本控制基线的价值。
2. **视觉验收发现遗漏**：对话页输入框下方残留浅色渐变（`from-[#f4f5f7]` 为任意值渐变 stop，不在批量映射内），已单独修复并重截图确认。
3. **一次性控制台报错**：快速逐页导航时出现 `SyntaxError`（dev 编译竞态），chunk 内容检查无乱码、重载不复现（0 新错误），确认为 dev 环境瞬态，非代码缺陷。
