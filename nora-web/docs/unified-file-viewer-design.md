# Nora 统一文件查看器设计

日期：2026-09-30。状态：已实现，连接真实服务并完成模型与浏览器联调。

目标：助手交付真实文件，用户在对话旁直接阅读、核对、下载和继续提问；资料、工作区、任务结果共用这一套打开行为。

## 1. 已确定的产品决策

1. 桌面采用对话与文件并排的工作区，查看器按需出现；窄屏采用单页文件视图。
2. 正式报告、导出表格、图表等以真实文件为内容来源。聊天保留结论和文件入口。
3. 提供一个 `open_file` 工具。模型提交文件引用，由服务端验证，前端选择渲染器。
4. 当前轮次可请求自动展示一次；用户点击优先。刷新、历史回放、后台任务不会自动打开文件。
5. 查看器默认只读。工作区的现有编辑能力通过明确的「编辑」动作进入，保存与未保存提示继续生效。
6. 相册保留缩略图集合；配置差异、执行状态等保留业务卡片。它们引用的文件通过统一入口查看。
7. 复用已有预览组件、媒体缓存和成果登记，不增加另一套成果内容表。

## 3. 页面与交互

### 3.1 桌面布局

```text
┌──────────┬────────────────────────┬────────────────────────────────┐
│ Nora 导航│ 对话标题               │ 报告.md / 记录.csv              │
│          ├────────────────────────┼────────────────────────────────┤
│ 助手     │ 用户需求               │ 文件名、来源、更新时间          │
│ 资料     │ 简短结论               │ 预览 / 源码   引用 下载 扩展 关闭│
│ 任务     │ 已交付文件清单         ├────────────────────────────────┤
│          │ [报告.md] [记录.csv]   │ 文件内容                       │
│ 设置     │                        │                                │
│          │ 继续提问输入框         │                                │
└──────────┴────────────────────────┴────────────────────────────────┘
```

- 无打开文件时，沿用当前页面布局。
- 内容工作区宽度达到 840px 时启用并排；对话最小宽度 340px，查看器最小宽度 480px。主导航优先收为图标栏，避免占用阅读空间。
- 查看器默认占内容工作区 55%，可拖动至 45%–70%，同时受两侧最小宽度约束；宽度偏好保存在本地。拖动分隔条提供键盘操作与可访问名称。
- 查看器处于文件中心时覆盖当前内容区右侧，文件列表仍可操作。相同资源复用同一标签页。
- 「扩展阅读」暂时占据内容工作区；退出后恢复对话、查看器比例和阅读位置。保持应用内布局，不使用浏览器 Fullscreen API。

### 3.2 窄屏布局

- 内容工作区不足 840px 时，点击文件进入全宽文件视图，顶部显示「返回对话」或「返回资料」。
- 原页面状态、输入草稿和滚动位置保留；返回不会重新请求或重发消息。
- 不挤出极窄的对话列。标签页与工具条可折叠，主要操作保持可见。
- 自动交付只显示文件卡片和「查看报告」动作，窄屏不自动切走用户正在阅读的对话。

### 3.3 文件入口

| 入口 | 打开行为 |
|---|---|
| 聊天成果卡片、工具结果中的文件行 | 手动打开指定文件，保持会话路由与输入草稿 |
| 文件中心、首页最近文件 | 打开文件中心资源；沿用当前列表的前后导航 |
| 工作区列表 | 目录仍进入目录；文件进入查看器 |
| 已保存成果、任务结果 | 打开资源，提供「来源会话」动作 |
| 相册缩略图、媒体缓存 | 图片或视频进入同一查看器，并传递当前媒体集合 |
| 明确的查看器深链 | 服务端验证后打开；关闭仅移除查看参数 |

深链采用当前页面的 `?viewer=<编码后的规范引用>`。旧 `/files?open=<id>`、`/files?workspace=<path>` 保留适配：文件目标打开查看器，目录目标进入目录；不会把目录伪装成文件。

### 3.4 查看器工具条

文件名与来源始终可见；路径在详情中展开。动作按能力显示：

- **预览 / 源码**：Markdown、CSV、JSON、HTML 可切换；媒体与 PDF 不显示无效切换。
- **引用到对话**：向原会话输入框加入文件引用 chip，不自动发送、不把全文塞进输入框。服务端在发送时再次验证和读取；继续遵守现有引用预算。
- **下载**：下载原文件，保留真实文件名与 MIME。没有原始字节的临时历史视图显示「保存为文件」。
- **编辑**：仅对支持写入的工作区文本文件显示，进入现有编辑流程。未保存时切换、关闭、返回必须提供保存/放弃/继续编辑。
- **刷新**：主动重新验证并读取最新内容，不使用过期预览缓存。
- **扩展阅读 / 关闭**：关闭查看器不删除文件、不撤销任务。

最多保留 8 个打开标签页；第 9 个替换最近最少使用的非活动只读标签页。正在编辑的标签页不自动淘汰。媒体集合的左右切换复用同一标签页，不为每张照片开标签。

快捷键在查看器拥有焦点时生效：Esc 退出扩展阅读，再关闭查看器；媒体集合或列表的左右键切换文件。输入框、文本选择、媒体控制和已有灯箱优先消费自己的按键。对话中的 Esc 不误关文件。

## 4. 内容与文件来源

### 4.1 可接受的资源引用

| 引用 | 权威来源 | 规则 |
|---|---|---|
| `workspace:reports/分析.md` | 工作区真实文件 | 服务端规范化相对路径，限制在工作区真实根目录内，检查符号链接逃逸 |
| `file:123` | 文件中心记录与原始文件 | 验证 id、访问权限、未删除状态；名称与类型取自真实元数据 |
| `media:<cacheKey>` | 现有媒体缓存 | 通过缓存键解析；凭据留在服务端，失效缓存返回明确错误 |

模型不能传任意绝对路径、原始 URL、HTML 正文或自定义组件名。已有整机文件操作工具维持自己的权限边界；需要交付整机文件时先通过已授权操作复制到工作区，再打开。

文件中心 `file:123` 与某个工作区路径，即使名称相同，也属于不同资源。稳定标识为服务端返回的规范化 `target`。

历史相册中尚无缓存键的 URL 经现有媒体缓存服务校验和代理后获得资源引用，不在浏览器直连远程地址，不强制导入文件中心。缓存失效时可重取；手机离线且无缓存时如实显示不可用。长期保存仍使用现有「保存到文件中心」。

### 4.2 格式支持

| 格式 | 阅读 | 源码/原件 | 实现依据 |
|---|---|---|---|
| Markdown | 标题、表格、引用、代码、图片 | UTF-8 源码、原文件下载 | 复用共享 `Markdown` |
| TXT、代码、JSON | 等宽文本；JSON 可格式化显示 | 保留原始字节 | 复用文本预览；格式化不写回 |
| CSV、TSV | 正确解析后呈现表格，标明预览行数 | 原始文本与下载 | 使用 Papa Parse，实施时用 pnpm 安装依赖；不能手写 split 解析 |
| 图片、音视频 | 缩放/播放、集合内切换 | 原图/原片下载 | 复用图片、媒体预览与缓存档位处理 |
| PDF | 浏览器原生 PDF 阅读 | 原件下载 | 复用 PDF 预览 |
| 文件中心 Word、Excel | 沿用现有提取文本/表格预览 | 原件下载 | 保留现有契约，明确标注为提取内容 |
| 工作区 Office 二进制 | 文件信息与原件下载；提供已有解析能力时再显示预览 | 原件下载 | 不冒充高保真 Office 查看器，不用占位内容 |
| HTML | 隔离的静态页面预览 | 源码与原件下载 | `iframe sandbox=""`；经鉴权读取到内存后用 `srcdoc` |
| 不支持的二进制 | 类型、大小与不支持提示 | 原件下载 | 明确状态，保持原文件可用 |

HTML 第一版支持静态页面。除空 sandbox 外，srcdoc 的首个元素必须是查看器写入的 CSP meta：`default-src 'none'; img-src data: blob:; style-src 'unsafe-inline'; font-src data:; form-action 'none'; base-uri 'none'`。渲染前用 DOM 解析移除作者提供的 base、刷新 meta 和可导航链接属性；保留内容正文。脚本、表单、顶层导航、弹窗及外部资源访问关闭；源内容不可读取应用凭据。互动网页运行属于浏览器工具的独立能力，不通过文件查看器默认启用。

CSV/TSV 默认展示前 200 行，超过时显示「已显示前 200 行，下载查看完整数据」；单元格作为文本呈现。文本与源码预览上限 2 MiB，超限时告知截断并保留完整下载。二进制原件使用现有读取/下载能力，新增工作区音视频下载需支持流式响应和 Range；不得先把大视频整体读进 JVM 或浏览器内存。

## 5. 工具与 API 契约

### 5.1 `open_file`

```json
{
  "targets": ["workspace:reports/巡检分析.md", "workspace:reports/巡检记录.csv"],
  "focus": "workspace:reports/巡检分析.md",
  "intent": "deliver"
}
```

- `targets` 必填，1–20 个引用，去重后逐一验证；单文件同样使用数组。
- `focus` 可选，必须属于 targets。失败时选择首个有效文件；不会打开失败目标。
- `intent` 为 `inspect` 或 `deliver`，默认 inspect。
- inspect：请求查看已有文件，不登记成果。
- deliver：请求交付，并将工作区文件登记到现有 `saved_artifact`。文件中心或缓存资源允许展示，但不伪装成新生成的工作区成果。
- 目录、缺失资源、未授权目标返回逐项错误；部分有效时保留有效文件，并使用现有 partial 状态。
- 工具是低风险展示请求；它不生成、修改、删除原文件，不执行文件内容。

模型说明：完成报告先调用既有写文件工具，确认写入成功，再用 open_file 交付。工具返回「已验证文件，可通过入口查看」，不声称用户一定已看到面板；后台运行、窄屏及用户关闭查看器时前端可能不自动展示。

### 5.2 资源描述

```ts
interface ViewerFile {
  target: string;              // 服务端规范化引用，稳定身份
  name: string;                // 真实文件名
  mimeType: string;
  size: number;                // 字节数
  modifiedAt: string | null;
  version: string;             // 服务端提供的缓存校验值
  previewKind: string;         // 服务端类型提示，前端只接受已注册渲染器
  capabilities: {
    preview: boolean;
    source: boolean;
    download: boolean;
    edit: boolean;
    attach: boolean;
  };
  delivery?: {
    status: "registered" | "failed" | "not_requested";
    artifactId?: number;
    error?: string;
  };
}
```

能力以实际权限与源服务能力计算。描述中不保存授权令牌、远程凭据、base64、文件正文或带 token 的 URL。来源会话与步骤身份从服务端当前运行取得，模型不能指定别人的会话。

新增 `POST /api/viewer/resolve`，请求 `{ targets: string[] }`，返回 `{ files: ViewerFile[], errors: { target, code, message }[] }`，使用项目既有 `{code,data,message}` 信封。工具执行与 HTTP 路由复用同一服务方法；网关将 `/api/viewer/**` 路由到 agent-service。

新契约层 `viewerApi.ts` 使用 `requestJson`。实际内容读取由这里复用 filesApi、workspaceApi、mediaCacheApi；组件不直连 fetch。媒体按缓存键获取原件需要在现有 media API 补充鉴权的键查找/读取入口。工作区原件接口补充正确 MIME、下载文件名、流式与 Range 支持，不新建另一份存储。

### 5.3 复用步骤事件

在现有 `ChatStepResult` / `ChatStepDto.StepResult` 上增加：

```ts
files?: ViewerFile[];
focusTarget?: string;
fileErrors?: Array<{ target: string; code: string; message: string }>;
```

ToolOutcome 的可选文件结果传给 ToolStepEmitter，进入完成或部分完成的 `step` 事件，同时沿用现有步骤保存、重连与历史恢复。模型侧 content 只接收有界的真实文件摘要；正文不在工具结果中重复发送。

实现必须逐一覆盖 DTO 便捷构造、步骤更新/复制、持久化序列化、历史读取与前端合并。只有明确的结构化 files 能成为新成果卡片；不能扫描自然语言路径或把任意 JSON 推断为打开指令。

## 6. 自动打开与回放规则

| 情况 | 文件入口 | 自动切换查看器 |
|---|---|---|
| 当前可见会话、本客户端发起的轮次第一次 open_file | 显示/更新 | 宽屏且用户尚未主动操作查看器时可打开 |
| 同一轮次后续交付 | 合并新增文件 | 不抢占，提示新增数量 |
| 用户点击文件 | 显示 | 始终手动打开指定文件 |
| 用户在轮次中关闭、切换或编辑文件 | 正常保留 | 本轮后续自动请求受抑制 |
| SSE 断线重连、重放相同步骤 | 按步骤 id 合并 | 不重新自动打开 |
| 刷新、读取历史、换浏览器 | 恢复卡片 | 不自动打开 |
| 后台自动任务或其他会话 | 在任务/对应会话留入口 | 不影响当前工作区 |
| 窄屏 | 显示卡片 | 等用户点击 |

去重与自动打开资格由 `(runId, stepId)` 和当前订阅上下文共同决定。每次打开 SSE 连接先记录本次订阅已经存在的步骤基线，基线内及重放帧永远无自动资格；重连时整条连接只恢复数据，不推导新 focus。用户抑制标记只属于当前 run，下一次主动发起的需求重新建立资格。

查看器成功显示与否属于客户端状态，不决定后台文件写入、成果登记或任务成功。不要增加等待前端确认才能结束的工具调用。

## 7. 文件更新、缓存与保存

- 每次打开先解析真实元数据，再按 `(target, version)` 取预览缓存。复用现有请求序号守卫或 AbortController，快速切换只接受当前目标的响应。
- 缓存最多 30 份预览，并限制文本预览总量 16 MiB；原始音视频与图片字节交给浏览器和现有媒体缓存。
- 工作区 version 可用纳秒级修改时间与字节数组成弱校验值；它用于预览缓存，不作为编辑冲突判据。刷新强制重读。
- 当前可见查看器在对话本轮结束和窗口重新获得焦点时校验打开文件；没有变化不重载。编辑期间只提示外部变更，避免覆盖用户草稿。
- 同一路径内容更新时复用原标签页，清除旧内容缓存，提示「文件已更新」。历史卡片默认打开当前文件，明确标示；本设计不承诺历史版本归档。
- 开始编辑时记住读取内容/可靠内容哈希。保存前后端比较原内容，冲突返回 409；用户明确选择覆盖或重新加载。编辑锁定期间关闭/切换保护未保存内容。
- 文件真正写入成功与成果登记分别报告。登记失败显示「文件已保存，成果登记失败」，可用同一幂等 upsert 重试；不能假装资料页已有记录。
- 只有 deliver 且真实工作区文件才自动登记。记忆、配置、临时文件的日常读写不会污染已保存成果。
- 正式报告已有文件时，消息卡片提供打开和下载；普通回答仍可另存。历史 text 画廊另存时写入 `data.text` 的正文，不把整个展示协议再次写成报告。

## 8. 旧画廊迁移

| 类型 | 新交付 | 历史消息 |
|---|---|---|
| text | 真正的 Markdown 文件 + open_file | 原卡片继续可读；「展开阅读」进入临时只读视图，标示尚未保存，另存后得到真实引用 |
| files / 文件型 list | 经过验证的资源清单 | 原解析保留；workspace/file 点击改走统一入口 |
| media | 缩略图集合 + 媒体引用 | 保留原缩略图与拍摄信息，打开行为接入查看器 |
| table | 可交付数据写入 CSV；即时查询仍可内联 | 原表格继续呈现 |
| diff / timeline / keyvalue / 通用 list | 紧凑业务卡片 | 保留 |

临时历史视图是前端内部类型，不开放为模型可调用 target；正文只在内存，不能冒充磁盘文件。新文件方案稳定前保留 v2/v3/v4 与 nora-gallery 的历史解析，不重写历史消息或批量转换旧文件。

同步更新 ChatContextAssembler 的交付说明与「产物画廊指南」技能：报告和真实文件使用 open_file，媒体集合与业务状态使用对应展示能力。新旧指令不能同时强制报告输出 nora-artifacts。

## 9. 实现边界与文件分工

| 位置 | 责任 |
|---|---|
| 全局布局 / `App.tsx` 对应共享 Layout | 放置唯一查看器宿主，响应宽屏与窄屏布局 |
| `hooks/useFileViewer.ts` | 改为共享 Zustand 状态，标签页、选中、缓存、来源上下文；不 persist 文件正文 |
| `types` + `lib/services/viewerApi.ts` | 引用与资源类型、解析和读取契约 |
| `components/files/viewer` | 提取已有内容渲染分发；共享宿主、工具条及各格式组件 |
| 文件页、最近文件、WorkspaceBrowser、SavedArtifactsView、画廊链接 | 全部调用统一 open，不各自创建预览弹窗 |
| 聊天步骤接收与消息组件 | 结构化文件清单、按 run 的自动展示仲裁、引用回输入框 |
| ChatToolsSpec / ChatToolExecutor / RiskClassifier | 注册与执行 open_file，低风险分类、真实目标校验 |
| ChatStepDto / ToolStepEmitter / 步骤保存与恢复链路 | 传递并保存可选 files 字段，不改变现有事件类型 |
| AgentWorkspaceController / 媒体 API / 网关 | 原件响应、媒体键查询与 viewer 路由 |
| ChatContextAssembler / 画廊技能 | 消除重复的文件交付协议要求 |

格式继续使用独立渲染组件，统一宿主不承接文件管理、工具执行、内容生成。每种源的分流放在契约层；不增加插件框架、转换任务队列或完整 IDE。

## 10. 实施顺序与验收

### 第一批：统一用户打开路径

共享查看器、资源解析、Markdown/文本/CSV、既有文件中心预览、工作区文件打开、深链、响应式布局；现有编辑入口与冲突保护一起接通。用户点击现有文件即可实测，没有依赖模型新协议的空壳阶段。

### 第二批：真实交付与回放

open_file、步骤字段、成果登记、聊天卡片、引用到对话、自动展示规则、刷新与断线重连。完成真实「写报告 → 打开 → 修改 → 再查看」闭环。

### 第三批：入口迁移收尾

相册/媒体缓存、历史报告、任务与成果入口全部接入；更新提示词和技能；确认新交付不再需要报告 JSON。保留历史解析，清除已经没有调用者的独立预览宿主。

### 必须通过的真实服务与浏览器验收

| 场景 | 可观察的通过条件 |
